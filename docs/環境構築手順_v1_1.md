# 環境構築手順（段階0）

| 項目 | 内容 |
|---|---|
| 版数 | 1.1 |
| 前提環境 | Windows / コマンドプロンプト |
| 検証済みバージョン | Next.js 16.3.1、Prisma 7.9.1、PostgreSQL 16 |

**ゴール**：テキストを入力して保存し、ページを再読み込みしても残っていることを確認する。

これだけです。カード機能もSM-2も作りません。選定した技術が手に馴染むかを確かめるのが目的です。

**所要時間の目安**：2〜4時間（初回は詰まる前提）

## 0. 作業を始める前に

### ターミナルは2つ開く

`npm run dev` はサーバーを起動しっぱなしにするため、そのターミナルは占有される。

- **タブ1**：`npm run dev`（ログが流れる。**エラーはここに出る**）
- **タブ2**：git、docker、prisma などの作業用

新しいタブは `Ctrl+Shift+T`。開いたら毎回 `cd remind-app` を忘れない。

### Docker Desktop を先に起動する

タスクトレイのクジラアイコンが安定するまで待つ。起動していないと以下が出る。

```
open //./pipe/dockerDesktopLinuxEngine: The system cannot find the file specified.
```

PCを再起動すると毎回この状態に戻る。

### コマンドの方言に注意

手順書やWeb上の記事は Unix系（Mac/Linux）前提で書かれていることが多い。コマンドプロンプトでは以下が使えない。

| Unix系 | コマンドプロンプト |
|---|---|
| `cat ファイル` | `type ファイル` |
| `grep 文字列 ファイル` | `findstr 文字列 ファイル` |
| `ls` | `dir` |
| `rm -rf フォルダ` | `rmdir /s /q フォルダ` |

> 統一したい場合は Git Bash か VS Code の内蔵ターミナルを使う。以降は**コマンドプロンプト前提**で記述する。

## Step 1：プロジェクトを作る

```bash
npx create-next-app@latest remind-app
```

最初にこう聞かれる。

```
? Would you like to use the recommended Next.js defaults?
>   Yes, use recommended defaults
    No, customize settings
```

**`No, customize settings` を選ぶ。** 推奨デフォルトは `src/` ディレクトリなしになっており、以降の手順（`src/lib/`、`src/app/`）と食い違うため。

| 質問 | 回答 | 理由 |
|---|---|---|
| TypeScript | **Yes** | 技術選定の通り |
| ESLint | **Yes** | 段階4のCIでLintを回すため |
| React Compiler | **No** | 今は不要 |
| Tailwind CSS | **Yes** | CSSを別ファイルで管理せずに済む |
| `src/` directory | **Yes** | **必須。以降の手順の前提** |
| App Router | **Yes** | 現在の標準 |
| import alias | **No**（デフォルトのまま） | `@/*` のまま使う |
| AGENTS.md | どちらでも | 不要なら No |

> 質問の項目と並び順はバージョンで変わる。表と食い違っても、上記の方針に合わせれば問題ない。見慣れない項目は No でよい。

```bash
cd remind-app
npm run dev
```

ブラウザで `http://localhost:3000` を開き、Next.jsの初期画面が出れば成功。

### コミットについて

`create-next-app` は `git init` と初回コミットまで自動で行う。したがってここで `git add -A` しても、

```
nothing to commit, working tree clean
```

と出る。**これは失敗ではなく、すでにコミット済みという意味。** `git log --oneline` で確認できる。

### 改行コードの警告を止める

Windowsでは `git add` のたびに以下が出る。

```
warning: in the working copy of 'package.json', LF will be replaced by CRLF ...
```

エラーではないが、将来 Docker（Linux上）でシェルスクリプトを動かす際の事故要因になるため、自動変換を切っておく。

```bash
git config core.autocrlf false
```

> 以降、各Stepの終わりで必ずコミットする。開発プロセスが見えること自体に価値がある。

## Step 2：PostgreSQLをDockerで立てる

プロジェクト直下に `docker-compose.yml` を作る。

```yaml
services:
  db:
    image: postgres:16
    container_name: remind-db
    restart: unless-stopped
    environment:
      POSTGRES_USER: remind
      POSTGRES_PASSWORD: remind_local_pw
      POSTGRES_DB: remind
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

> YAMLはインデントがずれると動かない。エディタが開けない場合、Git Bash なら `cat > docker-compose.yml << 'EOF'` 〜 `EOF` で流し込める。

起動する。

```bash
docker compose up -d
docker compose ps
```

`STATUS` が **`Up 16 seconds`** のように表示されれば成功。Compose のバージョンによって `running` と表記される場合もあるが、同じ状態を指す。

接続まで確認する場合。

```bash
docker compose exec db pg_isready -U remind
```

`accepting connections` と出れば完璧。

> `docker compose exec` の直後は**サービス名**（＝`db`）を書く。`docker compose exec pg_isready` のようにサービス名を省くと `service "pg_isready" is not running` になる。

初回は `postgres:16` のイメージ取得で数分かかる。止まって見えても待つ。

> `volumes` を書いているのが重要。これがないとコンテナを消したときにデータも消える。

**コミットする。**

## Step 3：Prismaを入れる

```bash
npm install prisma --save-dev
npm install @prisma/client
npm install @prisma/adapter-pg
npx prisma init --datasource-provider postgresql
```

> **Prisma 7 系では `@prisma/adapter-pg` が必須。** 6系まではDBドライバが内蔵されていたが、7系では外部アダプタを明示的に渡す設計に変わった（Step 5で使う）。

`.env` が生成されるので、`DATABASE_URL` を書き換える。

```
DATABASE_URL="postgresql://remind:remind_local_pw@localhost:5432/remind?schema=public"
```

> **ホスト名は `localhost`。`remind-db` ではない。** `remind-db` は `container_name` であり、Dockerネットワークの**内側**でしか名前解決できない。今はWindows側からポート転送経由で繋ぐため `localhost` を使う。
>
> 将来アプリ自体をDocker化する段階3以降では、逆に `remind-db` が正解になる。`P1001: Can't reach database server at 'remind-db:5432'` はこの取り違えが原因。

`.env` が `.gitignore` に入っていることを確認する。

```bash
findstr env .gitignore
```

入っていなければ追記する。

```bash
echo .env>> .gitignore
```

> `>>` の前にスペースを入れない。余計な空白ごと書き込まれる。

> パスワードをGitに載せないため。今はローカル用だが、習慣として最初から徹底する。

`prisma/schema.prisma` の末尾に追記。

```prisma
  id        String   @id @default(cuid())
  body      String
  updatedAt DateTime @updatedAt

```

> これは検証用の仮テーブル。本番のCard／Blank／BlankLogは後で作り直す。

データベースに反映する。

```bash

```

```bash
npx prisma studio
```

ブラウザで `Note` テーブルが見えれば成功（中身は空でよい）。確認できたら `Ctrl+C` で止める。

**コミットする。**

### Prisma Client の生成先を確認する

```bash
npx prisma generate
```

出力の最終行に注目する。

```
✔ Generated Prisma Client (7.9.1) to .\src\generated\prisma
```

**Prisma 7 系ではプロジェクト内（`src/generated/prisma`）に生成される。** 6系までの `node_modules/.prisma/client` ではない。この差分が Step 5 の import 文に直結する。

生成物はGitに含めない。

```bash
echo /src/generated>> .gitignore
```

> `npx prisma generate` の実行時に `バッチ ジョブを終了しますか (Y/N)?` と聞かれることがある（直前に `Ctrl+C` を押した影響）。ここで `y` を選ぶと**コマンドが実行されずに終了する。必ず `n`。**

## Step 5：保存用のAPIを作る

**ADR-007の方針に従い、ロジックは `lib/` に置く。**

### 5-1. Prisma Client を共有する

`src/lib/prisma.ts` を作る。

```typescript
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "../generated/prisma/client";

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL });

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };

export const prisma = globalForPrisma.prisma ?? new PrismaClient({ adapter });

if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;
```

このファイルには2つの意図がある。

**① アダプタの注入**（Prisma 7 の要求）
`new PrismaClient()` を引数なしで呼ぶと以下で落ちる。

```
PrismaClientInitializationError: PrismaClient was instantiated without any options.
A driver adapter is required to connect to your database.
```

**② インスタンスの共有**
開発中はファイル保存のたびにモジュールが再読み込みされる。その都度 `new PrismaClient()` すると接続が増え続け、やがて枯渇する。`globalThis` に退避させておくのが定石。

> **import 元は `../generated/prisma/client`。** フォルダ指定（`../generated/prisma`）では解決できない。Prisma 7 は `index.ts` を生成しないため、エントリファイル名まで書く必要がある。
> 実際の中身は `dir /b src\generated\prisma` で確認できる。

### 5-2. DB操作を書く

`src/lib/notes.ts` を作る。

```typescript
import { prisma } from "./prisma";

const FIXED_ID = "singleton";

export async function getNote(): Promise<string> {
  const note = await prisma.note.findUnique({ where: { id: FIXED_ID } });
  return note?.body ?? "";
}

export async function saveNote(body: string): Promise<void> {
  await prisma.note.upsert({
    where: { id: FIXED_ID },
    update: { body },
    create: { id: FIXED_ID, body },
  });
}
```

### 5-3. エンドポイントを作る

`src/app/api/note/route.ts` を作る。**薄い層に留める。**

```typescript
import { NextResponse } from "next/server";
import { getNote, saveNote } from "@/lib/notes";

export async function GET() {
  return NextResponse.json({ body: await getNote() });
}

export async function POST(req: Request) {
  const { body } = await req.json();
  await saveNote(body);
  return NextResponse.json({ ok: true });
}
```

> `route.ts` にはDB操作を書いていない。呼び出すだけ。この分割を最初から守る。

> App Router では**フォルダ構成がそのままURLになる**。`src/app/api/note/route.ts` が `/api/note` に対応する。ファイル名 `route.ts` は固定の決まりで、`routes.ts` や `Route.ts` では認識されず 404 になる。

## Step 6：画面を作る

`src/app/page.tsx` を丸ごと置き換える。

```tsx
"use client";

import { useEffect, useState } from "react";

export default function Home() {
  const [text, setText] = useState("");
  const [status, setStatus] = useState("読み込み中");

  useEffect(() => {
    fetch("/api/note")
      .then((r) => r.json())
      .then((d) => {
        setText(d.body);
        setStatus("読み込み完了");
      });
  }, []);

  const save = async () => {
    setStatus("保存中");
    await fetch("/api/note", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ body: text }),
    });
    setStatus("保存しました");
  };

  return (
    <main className="p-8 max-w-2xl mx-auto">
      <h1 className="text-xl mb-4">保存テスト</h1>
      <textarea
        className="w-full h-64 border p-2"
        value={text}
        onChange={(e) => setText(e.target.value)}
      />
      <div className="mt-2 flex gap-4 items-center">
        <button onClick={save} className="border px-4 py-2">
          保存
        </button>
        <span className="text-sm text-gray-500">{status}</span>
      </div>
    </main>
  );
}
```

## エラーの切り分け方

**ブラウザに出るエラーは、多くの場合ただの二次症状。**

たとえば `Failed to execute 'json' on 'Response': Unexpected end of JSON input` は、「APIが500を返したためJSONが空だった」というだけで、原因ではない。**必ず `npm run dev` を動かしているターミナル側を見る。**

APIが呼ばれているかは、ブラウザの開発者ツール（F12）→ Network タブで確認する。

| ステータス | 意味 | 見る場所 |
|---|---|---|
| リクエストが飛ばない | ボタンのイベントが繋がっていない | `page.tsx` |
| 404 | パスかファイル名が違う | `src/app/api/note/route.ts` の位置 |
| 500 | サーバー側の問題 | **ターミナルのログ** |
| 200 なのに残らない | 書き込みは成功、読み出し側の問題 | `prisma studio` で中身を確認 |

## 詰まりやすい箇所

| 症状 | 原因の候補 |
|---|---|
| `The system cannot find the file specified`（pipe） | Docker Desktop が起動していない |
| `P1001: Can't reach database server at 'remind-db:5432'` | `DATABASE_URL` のホストが `localhost` になっていない |
| `ECONNREFUSED` | DBが起動していない。`docker compose ps` を確認 |
| `port 5432 already in use` | 別のPostgreSQLが動いている。`docker compose down` または既存を停止 |
| `Cannot find module '.prisma/client/default'` | Prisma 7 の生成先は `src/generated/prisma`。import 元を変える |
| `Module not found: Can't resolve '../generated/prisma'` | エントリまで指定する。`../generated/prisma/client` |
| `PrismaClient was instantiated without any options` | ドライバアダプタ未指定。`src/lib/prisma.ts` を参照 |
| 404 (Not Found) | ファイル名が `route.ts` か。拡張子が `.txt` になっていないか |
| `service "xxx" is not running` | `docker compose exec` の直後にサービス名 `db` を書いたか |
| `バッチ ジョブを終了しますか` で中断される | `y` ではなく `n` を選ぶ |
| `'cat' は認識されていません` | コマンドプロンプトでは `type` / `findstr` |
| ファイルを追加したのに認識されない | `npm run dev` を `Ctrl+C` で止めて再起動。それでも駄目なら `rmdir /s /q .next` |
